## 왜 이 앱인가

혼자 회의하면 결정이 미뤄지고, AI 한 명에게 물으면 반대 의견이 없습니다. 이 앱은 **역할을 나눠 순서대로 발언시키고, 마지막 역할이 앞선 답변을 검수**하게 합니다. 검수자는 다음을 반드시 지적합니다.

1. 근거 없는 숫자 (예: "전환 2%"의 출처가 없는 경우)
2. 예산과 연결되지 않은 실행 수치 (예: "방문 3,062명"에 채널 단가가 없는 경우)
3. 담당이 역할 이름으로만 적힌 액션
4. 개인정보·권한 관련 액션이 빠진 경우 (안건에 해당 신호가 있을 때)
5. 개발 답변의 API 계약·테스트·롤백 근거가 빠진 경우

CFO는 예산·객단가·전환율로 회수 필요 방문 수를 실제로 계산하고, Auditor는 그 계산을 다시 해 확인합니다. 개발 리드(DEV)는 기능보다 인터페이스 계약, 테스트 케이스, 배포·롤백 절차를 먼저 고정합니다.

## 🎬 AI HQ 라이브 관제 & 회의실

KPI 4카드 아래에 붙는 한 장짜리 관제 패널입니다. 새 기록을 만들지 않고 **아래 3단 회의창·체크리스트·회의록이 쓰는 같은 기록을 읽어서** 그립니다. 그래서 좌석·모니터·게이지가 본문과 어긋나는 일이 없습니다.

- **부서 모니터 (8분할, 기본 8 + 내가 추가한 부서)**: 부서마다 **다른 클레이 미니어처 방 사진** 한 장(크림 벽 · 원목 책상 · 모니터 뒷면 · 화분 · 선반 · 창으로 드는 오후 햇살)이 원목 프레임 안에 들어가고, 그 방을 맡은 AI가 **둥근 머리 · 니트 비니/후드/안경/헤드셋 · 손을 모은 클레이 피규어**로 방 가운데 스툴에 앉아 있습니다. 기본 8개 방은 모두 상시 담당 AI가 앉아 있고, `+ 부서 추가`로 만든 방만 회의 전 빈 방으로 남습니다.
- **🏛️ 중앙 회의실**: 8분할 위에 놓인 넓은 **원목 회의실 창**입니다. 큰 창으로 햇살이 드는 클레이 회의실 배경 위에 **긴 원목 타원 테이블**(머그·서류·화분·다리·그림자)이 놓이고, 역할 8명(추가 역할 포함)이 테이블 안쪽 4석·바깥쪽 4석에 앉습니다. 각 좌석은 **스툴에 앉은 클레이 피규어 + 이름표**이고, 회의 전에는 `빈 자리`(빈 스툴), `회의 시작`을 누르면 피규어가 나타나며 `착석`으로 바뀝니다.
- **ON AIR**: 지금 발언 차례인 좌석과 그 역할의 담당 부서 모니터에 빨간 비콘과 `ON AIR`가 켜지고, **한 줄 실시간 말풍선**(발언 첫 줄)이 회의 테이블 위와 그 부서 방 안에 뜹니다. 발언자는 자리에서 살짝 들썩이며 **손을 들고**, 담당 방의 피규어는 **숨쉬듯 움직이며 두 팔로 타이핑**합니다. 발언이 끝나면 좌석은 `보고 완료 ✓`, 모니터는 `보고 완료`로 식습니다.
- **아트 원칙**: 외부 CDN·Three.js·폰트 요청은 없습니다. 방 배경은 **이 앱을 위해 생성해 저장소에 넣은 WebP 9장(합계 약 300KB)** 이고, 캐릭터·테이블·스툴은 **`art.js`가 그리는 손그림 SVG**(클레이 느낌의 방사형 그라디언트, 그림자, 깜빡임)입니다. 역할별로 머리(비니·버즈·야구모자·번·단발)·안경/헤드셋·옷깃(니트·후드·타이·조끼)이 다르고, 사용자가 추가한 역할은 같은 종류라도 얼굴이 다릅니다. 애니메이션은 `prefers-reduced-motion: reduce`에서 모두 멈춥니다.
- **비주얼 톤**: 사용자가 준 레퍼런스 2장(우드 아치 · 크림 벽 · 사선 햇살 · 클레이/펠트 소품 · 블라인드박스 피규어)을 기준으로, 페이지 전체를 크림/오트밀/월넛/테라코타/머스타드로 맞췄습니다. 방 사진은 640×400 WebP(장당 22–31KB), 회의실은 1300×500 WebP(58KB)로 줄여 모바일에서도 바로 뜹니다.
- **CEO 결재 HUD**: `오늘 처리 안건`(오늘 발언이 있는 방 수) · `완료 액션`(이 방 완료/전체) · `결재율 %` + 게이지. 오른쪽 체크리스트를 누를 때마다 0.5초로 차오릅니다.
- 역할 → 모니터 대응은 `data.js`의 `ROLE_ROOM`(기획·개발·디자인·영상·마케팅·영업·운영·전체)에서 정합니다. 기본 8개 부서는 모두 담당 AI가 있어 `STANDBY`에서도 피규어가 앉아 있고, `+ 부서 추가`로 만든 방만 담당이 없을 때 빈 방으로 남습니다.
- 판단은 `core.js`의 `liveSnapshot()` 한 곳에서만 합니다(순수 함수, DOM·시계·저장 없음). 1440px는 모니터 2×2 벽 + 중앙 회의실이 한눈에, 390px는 2열 미니 모니터 + 컴팩트 회의실로 접힙니다.

| 전체 · 교차검수 | 문서 + 펜 필기 + 검수 렌즈 이동 | 필기 |
| 기획 | 코르크 보드 · 스티키 노트 · 마커 선이 그려지고 손가락이 짚음 | 보드 짚기 |
| 개발 | 코드 화면의 줄 스크롤 · 커서 깜빡임 · 화면 글로우 | 양손 타자 |
| 디자인 | 캔버스에 브러시 획이 그려짐 · 팔레트 스와치 점멸 | 펜 필기 |
| 영상 | 프리뷰 스윕 · 타임라인 클립 · 재생바 이동 | 타임라인 짚기 |
| 마케팅 | 막대가 자라남 · 추세선이 그려짐 | 차트 짚기 |
| 영업 | 제안서 페이지 넘김 · 승인 체크 | 손바닥 발표 |
| 운영·CS | 체크리스트 3단 체크 · 상태 램프 순차 점등 · 알림 핑 | 필기 |

- 지금 보고 있는 부서(`is-current`)는 소품 테두리와 글로우가 켜지고 피규어가 더 빠르게 움직입니다.
- `ON AIR`(발언 중)인 부서는 데스크 소품이 가장 빠르게 돌고 빨간 글로우가 붙습니다(그 순간 사람은 회의실에 있으므로 방은 `자리 비움`).
- 움직임은 모두 `art.js`가 그린 SVG와 `styles.css` 키프레임이며 외부 라이브러리·이미지가 없습니다. `prefers-reduced-motion: reduce`에서는 전부 멈춥니다.

### 회의 소집 · 회의 · 복귀

1. `회의 시작` → 판이 `data-presence="meeting"`으로 바뀌고, 각 방의 피규어가 `회의실`로 날아갑니다(`#hqTravel .traveler`, 55ms 간격·680ms 이동). 방은 `자리 비움` 칩과 빈 스툴로 남고, 회의실 좌석은 360ms부터 한 명씩 나타납니다.
2. 회의 중 발언자 좌석은 이름표가 살짝 올라가며 **상체 바운스(`seatBob`)·손들기(`clayHandUp`)·따뜻한 헤일로**로 강조되고, 회의실 말풍선이 그 좌석 위로 이동합니다. 나머지 7명은 **고개 끄덕임(`seatNod`)·펜 필기(`fig--write`)** 로 경청합니다.
3. 발언이 끝나 회의가 끝나면(`data-assembly="out"`) 8명이 각자 방으로 돌아가고, 회의실 좌석은 `보고 완료 ✓` 기록만 남긴 빈 의자가 됩니다. 각 방 피규어는 다시 자기 부서 작업을 시작합니다.
4. 이동은 Web Animations API로만 그리며 레이어는 `aria-hidden`입니다. 모션 최소화 설정이면 이동 없이 상태만 바뀝니다.

엔진(발언·좌석 상태)은 여전히 `liveSnapshot()` 하나가 정하고, `app.js`는 그 결과에 **자리(presence)** 만 얹어 그립니다.

## 무료 모드 (기본)

1. 부서를 고르고 안건을 적거나 샘플 3종 중 하나를 누릅니다.
2. `회의 시작`을 누르면 여덟 역할이 **순서대로** 발언합니다(약 0.4~0.5초 간격).
3. 발언이 나올 때마다 오른쪽 체크리스트에 액션이 쌓입니다(8역할 × 3건 = 24건).
4. 발언에 `답글`을 달면 그 역할이 내 말을 인용해 다시 답하고, 액션을 하나 추가합니다.
5. `이어서 토론`은 2라운드를 엽니다. 2라운드는 새 안건을 꺼내지 않고 적용 시점과 중단 기준만 정합니다.
6. 라운드가 끝나면 각 부서 아웃풋과 최종 통합 아웃풋이 그 프로젝트에 쌓입니다.

무료 엔진은 안건에서 숫자(예산·전환율·기간·목표)와 위험 신호(개인정보·결제·계약·보안)를 읽고, 도메인(출시·가격·성장·유지·채용·인프라·보안·재무·운영·콘텐츠·기획·디자인·영상·영업)에 맞춰 문장을 조립합니다. 같은 입력은 같은 결과를 냅니다(결정적).

## Pro 모드 (BYOK)

`Pro` 또는 톱니 버튼 → 제공자별 슬롯(OpenAI · Google Gemini · Anthropic Claude)에 모델 이름과 키를 넣고 `저장`. 세 슬롯을 한 화면에서 각각 저장·수정·삭제합니다.

- 키는 제공자별로 나뉘어 `localStorage`(`onetap.teamroom.pro.v2`)에 저장됩니다. 화면에는 앞 4자·뒤 4자만 보이고, 저장 후 입력칸은 비워져 빈 칸으로 저장해도 기존 키가 지워지지 않습니다.
- 이전 버전의 단일 키(`onetap.teamroom.pro.v1`)는 첫 실행 때 해당 제공자 슬롯으로 자동 이전되고, 옛 저장소는 지워집니다.
- 모달 상단과 톱니 옆에 `3/3 연결됨` / `1/3 연결 · 미연결 모델은 연결된 키로 자동 폴백`이 표시됩니다.
- 호출은 브라우저 → 해당 제공자 API로 직접 갑니다. 이 페이지에는 백엔드가 없고, 각 키는 그 제공자에게만 전송됩니다.
- 8개 역할을 **연속 호출**하며, 뒤 역할은 앞선 발언 전체를 프롬프트에 받습니다. Auditor는 특히 앞선 일곱 답변의 숫자를 인용·재계산하도록 지시됩니다.
- 역할별 배정 제공자: 기획·영상·교차검수 = Gemini, 개발·영업·재무 = Claude, 디자인·그로스 = GPT. 배정 제공자 키가 없으면 연결된 다른 제공자로 폴백하며, 폴백이 2사 이상이면 순서대로 돌아가며 호출합니다.
- 발언 카드에는 실제로 답한 모델(GPT/Gemini/Claude)과, 폴백일 때 `폴백` 배지가 붙습니다. 로스터 칩도 현재 연결 상태를 반영합니다.
- 프롬프트에는 고른 부서 이름(직접 추가한 부서 포함)과 참석 역할이 들어갑니다.
- Pro 라운드는 기본 8역할(기획·개발·디자인·영상·그로스·영업·재무·검수)만 호출합니다. 직접 추가한 역할은 무료 모드 라운드에서 발언하며, 추가한 부서(회의실)에서는 8역할이 그 부서 맥락으로 각자의 제공자에 호출됩니다.
- 응답은 `관점/제안/리스크/요청/액션` 형식으로 파싱되어 무료 모드와 같은 카드로 표시되고, `액션:` 줄은 체크리스트가 됩니다.
- 401/429/네트워크/형식 오류를 구분해 보여주고, 실패한 발언부터 다시 시도할 수 있습니다. 어느 제공자의 키가 거부됐는지는 그 턴에서 드러납니다.
- 기본 모델: OpenAI `gpt-4o-mini`, Gemini `gemini-3.5-flash-lite`, Claude `claude-sonnet-4-20250514`. 모델명은 자주 바뀌므로 404가 나면 발급 페이지의 현재 이름으로 바꾸세요. Gemini 기본값은 무료 티어(15 RPM · 500 RPD) 기준이고, `2.5-flash`가 12/1에 전환되어 `3.5-flash-lite`로 바꿨습니다. 기존 브라우저에 2.5가 저장돼 있으면 모달의 `기본 모델` 버튼으로 되돌리면 됩니다.
- OpenAI·Claude는 브라우저 직접 호출을 막는 경우가 있습니다. 그때는 아래 **웹 구독 브리지**를 켜면 됩니다.

## 웹 구독 브리지 (구독 중인 GPT·Claude를 키 없이 쓰기)

Pro 연결 모달의 OpenAI(GPT)·Anthropic(Claude) 슬롯에 `웹 구독 브리지로 사용`을 켜면 API 키 없이 Pro 회의를 돌릴 수 있습니다. 키가 있으면 키가 우선이고, 브리지는 키 없는 제공자에게만 적용됩니다.

1. 그 부서(예: 개발=Claude, 디자인=GPT) 차례가 오면 발언 자리에 **브리지 카드**가 뜨고 회의가 그 자리에서 잠깐 멈춥니다.
2. `질문 복사 + ChatGPT 열기`(또는 `Claude 열기`)를 누르면 현재 안건·앞선 팀 발언 요약·그 역할의 기준·요청한 답변 형식이 한 번에 클립보드에 복사되고 `chatgpt.com` / `claude.ai`가 새 탭으로 열립니다. 팝업이 막혀도 복사는 되고, 카드에 사이트 링크가 있습니다.
3. 받은 답을 카드의 입력칸에 붙여넣고 `답변 반영`을 누르면 자유 형식이든 `관점/제안/리스크/요청/액션` 형식이든 정리되어 그 부서 발언·디오라마 방·중앙 회의실·액션 체크리스트·프로젝트 아웃풋·최종 통합 아웃풋에 합쳐지고, 다음 부서가 이어서 발언합니다.
4. 웹에 물어보기 번거로우면 `무료 엔진으로 대신 채우기`로 그 자리를 채워 회의를 계속할 수 있습니다.

Gemini 키 하나 + GPT·Claude 브리지 조합이 가장 자연스럽습니다. Gemini 부서(기획·영상·검수)는 자동 호출되고, GPT·Claude 부서는 브리지 카드로 진행됩니다. 브리지로 켠 상태는 `브리지 2`처럼 표시되고, 키가 하나도 없어도 `0/3` 대신 `브리지 연결` 상태로 동작합니다.

## 내보내기

- `회의록` 카드: Markdown · TXT · JSON으로 저장하거나 Markdown을 클립보드로 복사합니다. 파일에는 부서 이름, 안건, 참석 역할, 모든 발언, 답글, 체크 상태가 들어갑니다. 파일 이름은 `onetap-team-room-{부서}-{YYYYMMDD}.{확장자}`입니다.
- `프로젝트 & 팀 아웃풋` 패널: 프로젝트 아웃풋만 `전체 복사` 또는 MD · TXT · JSON으로 저장합니다. JSON에는 참여 부서, 진행률, 부서별 아웃풋이 들어갑니다. 파일 이름은 `onetap-project-{부서}-{YYYYMMDD}.{확장자}`입니다.

## 검증

```bash
node test.js       # 단위 테스트 1183건 (data/core/i18n/art + 파일 위생)
python3 uitest.py  # headless Chrome E2E 422건 (데스크톱 1440×900, 모바일 390×844)
```

`uitest.py`는 로컬 HTTP 서버를 띄우고 실제 Chrome을 돌립니다. 확인 항목: 부팅 외부 요청 0건, 콘솔 에러 0, 가로 넘침 0, 8개 부서 전환·기록 유지·새로고침 유지, `+ 부서 추가`와 저장·삭제, 8인 릴레이 발언, 검수 7건 인용, 답글, 체크리스트 토글·영속, MD/TXT/JSON 다운로드, 복사, EN/KO 전환, 역할 이름 변경·추가, Pro 3사 슬롯·구 단일 키 이전·3사 동시 저장·부서별 분산 호출(8역할)·개별/전체 키 삭제·2사·1사 폴백·오류 표시, **웹 구독 브리지**(키 없이 GPT·Claude 카드, 질문 복사·새 탭, 답변 반영, 무료 엔진 대체, 새로고침 유지, EN/KO, Gemini 키 하이브리드, Gemini 기본 3.5-flash-lite·기본 모델 버튼), 대비 검사, **관제 패널**(모니터 8대·8개 방 피규어·`회의 시작` 시 `ON AIR`·8석 소집·회의 종료 `보고 완료`·결재 게이지·새로고침 뒤 복원·모바일 2열), **부서별 작업 애니메이션**(부서마다 다른 소품 8종·움직이는 SVG 부품·자세 클래스·현재 부서 강조), **회의 소집/복귀**(이동 피규어 8명·`자리 비움` 칩 8곳·8석 착석·발언자 손들기/바운스·경청 7명 필기·좌석을 따라가는 말풍선·종료 후 복귀), 그리고 **프로젝트 & 팀 아웃풋**(안건 실행 시 프로젝트 생성, 부서 아웃풋 8+최종, 개별/전체 복사, MD/TXT/JSON, 진행 중/완료 필터, 프로젝트 전환 시 기록·아웃풋 분리). 스크린샷은 `work/`에 저장합니다.
